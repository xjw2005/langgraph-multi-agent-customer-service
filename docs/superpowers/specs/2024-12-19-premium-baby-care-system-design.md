# 高端母婴智能客服系统设计规范

**项目**: 基于LangGraph的高端母婴市场多Agent智能客服系统  
**版本**: v1.0  
**日期**: 2024-12-19  
**状态**: 设计完成，待实施

---

## 1. 项目概述

### 1.1 目标
将现有通用电商客服系统完全重构为面向高端母婴市场的专业智能客服系统，实现M1-M3完整功能，包含完整的RAG系统和React网页端界面。

### 1.2 核心特性
- **多Agent协作**: Master + 选品 + 专业问答 + 推销 4个专业Agent
- **强RAG系统**: Chroma向量数据库 + 500-800条母婴知识库
- **高端定位**: 专业话术、品质导向、可信赖的沟通范式
- **完整前端**: React界面包含聊天、商品展示、用户画像、推荐卡片
- **容器化部署**: Docker多容器架构，便于演示和部署

## 3. Agent架构重构

### 3.1 现有 → 新架构映射

| 现有Agent | 新Agent | 职责变化 |
|-----------|---------|----------|
| RouterAgent | Master Agent | 路由 → 总控 + 回复合成 |
| ProductAgent | 选品Agent | 通用商品 → 母婴商品筛选 |
| OrderAgent | (移除) | 订单功能暂不需要 |
| HumanAgent | (保留) | 人工转接保持不变 |
| (新增) | 专业问答Agent | 基于RAG的母婴知识问答 |
| (新增) | 推销Agent | 合规的营销话术生成 |

### 3.2 Agent职责定义

#### Master Agent (总控Agent)
- **输入**: 用户消息 + 上下文 + 子Agent结果
- **职责**: 意图理解、任务分解、子Agent调度、冲突消解、最终回复合成
- **输出**: 面向用户的完整连贯回复
- **基于**: 现有RouterAgent重构

#### 选品Agent
- **输入**: 需求描述 + 用户画像 + 商品库
- **职责**: 基于约束条件筛选母婴商品、对比分析、适用场景匹配
- **输出**: 推荐商品列表 + 每条理由 + 引用证据
- **基于**: 现有ProductAgent重构

#### 专业问答Agent
- **输入**: 专业问题 + RAG上下文
- **职责**: 母婴护理知识、成分分析、使用指导、认证信息
- **输出**: 专业回答 + 引用来源标识
- **基于**: 全新开发

#### 推销Agent
- **输入**: 候选商品 + 活动规则片段
- **职责**: 在合规前提下生成高转化话术
- **输出**: 营销话术片段（由Master Agent决定采用）
- **基于**: 全新开发

## 5. RAG系统设计

### 5.1 知识库结构
- **护理知识** (200条): 新生儿护理、喂养指导、睡眠训练
- **营养知识** (150条): 辅食添加、营养搭配、过敏预防  
- **商品知识** (200条): 品牌介绍、成分解析、使用方法
- **发育知识** (150条): 月龄发育、里程碑、早教建议

### 5.2 检索流程
1. **查询改写**: 结合意图与槽位生成检索query
2. **混合检索**: 关键词(BM25) + 向量检索
3. **重排序**: 基于相关性和权威性重排
4. **引用约束**: 强制使用检索上下文，避免幻觉

### 5.3 向量化策略
- **模型**: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
- **分块**: 按知识点分块，每块200-500字
- **元数据**: 包含分类、权威性、更新时间等

## 10. 风险与对策

| 风险项 | 影响 | 对策 |
|--------|------|------|
| RAG检索准确性不足 | 回答质量下降 | 优化知识库质量，调整检索策略 |
| Agent协作复杂度高 | 开发周期延长 | 分阶段实施，先简化后优化 |
| 前端开发工作量大 | 资源不足 | 使用成熟UI库，复用现有组件 |
| 容器化部署复杂 | 部署困难 | 提供详细文档，简化配置 |
| 知识库数据准备 | 内容质量参差 | 建立数据标准，分批验证 |
